My todos

    Week 4 documentation

    Application description

    It's a simple todo application that allows users to add and remove tasks from a list using frontend and backend with MySQL database.

    Frontend -> Backend -> Database communication works

    Communication between all the layers of the application are available to see on the website. Screenshot of a succesful get request from the backend which is displayed on the frontend.

    Database persistance

    Adding tasks to the list which are displayed on the frontend and stored in the database. Deleting the MySQL pod in rahti and checking back to see if the tasks are still there.

    Pod Recovery

    Deleting the backend pod in rahti and the controller automatically instantly deployed another pod to replace the deleted one.

    A new pod is created because the cluster expects to have a desired amount of pods running at all times. If it detects that a pod is missing it will try to create one automatically.
    The resource responsible for this action is a kubernetes controller.

    Scaling Experiment

    Scaled the backend replicas to 4 and checked them in rahti. The frontend is able to communicate with the replicas because a backend service is automatically distributing the requests.

    Application Update

    Updated the frontend version to 1.0.1 and reployed the application. changing the version in yaml. after saving the service automatically deployed the new version of the frontend.

    Challenges

    One of the challenges I faced during the homework was the deployment of the application to rahti. There's multiple resources that need to be deployed and configured somewhat correctly for it to work. I solved issues by reading documentation and googling the errors I was getting.
